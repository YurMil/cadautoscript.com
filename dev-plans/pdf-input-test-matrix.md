# PDF Input Test Matrix (issue #100)

The PDF utilities accept arbitrary user files, so malformed input is normal
traffic, not an edge case. This is the matrix each tool is expected to survive:
**a clear message, never a freeze and never a silent skip.**

Generate the disposable fixtures with:

```bash
node scripts/make-pdf-fixtures.mjs
```

## Matrix

| # | Input | Fixture | Expected class | Message shown |
|---|---|---|---|---|
| 1 | Zero-byte file | `empty.pdf` | `empty` | "This file is empty." |
| 2 | Non-PDF renamed to `.pdf` (e.g. an HTML error page) | `not-a-pdf.pdf` | `not-pdf` | "This is not a PDF file." |
| 3 | Larger than the size cap (200 MB default) | manual | `too-large` | "This file is too large to process in the browser." |
| 4 | Valid header, truncated body | `truncated.pdf` | `corrupt` (parser) | "This PDF appears to be damaged…" |
| 5 | Signature only, no objects | `header-only.pdf` | `corrupt` (parser) | as above |
| 6 | Valid signature, random bytes | `garbage-body.pdf` | `corrupt` (parser) | as above |
| 7 | Parseable but zero pages | `no-pages.pdf` | `no-pages` (parser) | "This PDF contains no readable pages." |
| 8 | Password-protected | manual | `encrypted` | "This PDF is password-protected…" |
| 9 | Unknown parser failure (dead worker, OOM) | — | `generic` | "This PDF could not be processed. Skipping it." |
| 10 | Batch: one bad file among good ones | mix any above | per file | bad file named and skipped, **good files still processed** |

Cases 1–3 are caught **before** parsing by `validatePdfFile()`; 4–9 are
classified from the parser's own failure by `classifyPdfError()`. Both live in
`src/lib/pdfValidation.ts` so the tools cannot drift apart in what they accept.

## Automated coverage

`validatePdfFile()` and `classifyPdfError()` are verified against the generated
fixtures and against pdf.js / pdf-lib error shapes — 12 assertions, run with:

```bash
node --experimental-strip-types scripts/../src/lib/pdfValidation.ts
```

(The check script itself lives with the PR that introduced it; the fixtures are
regenerated by the command above.)

## Tool status

| Tool | Where it lives | Hardened |
|---|---|---|
| PDF Number Extractor | in-repo (`src/components/PdfNumberExtractor`) | ✅ pre-parse validation + classified parser failures, localized |
| PDF Master | standalone app repo | ⬜ pending — port `pdfValidation.ts` |
| PDF Batch Signer | standalone app repo | ⬜ pending |
| PDF BOM Extractor | standalone app repo | ⬜ pending |

Standalone apps cannot import from the site's `src/`, so hardening them means
copying `pdfValidation.ts` into each app (it has no dependencies) and mapping
the returned kind to that app's own strings.

## Manual pass (per tool)

1. Run `node scripts/make-pdf-fixtures.mjs`.
2. Drop **all** fixtures in at once.
3. Confirm: every bad file is named with a reason, the tool stays responsive,
   and any valid files in the batch still produce results.
4. Repeat with a password-protected PDF and a >200 MB file.
